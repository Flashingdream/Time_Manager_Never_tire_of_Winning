# MemorandumIndexView.vue 前端接口设计文档
> 📌 **页面用途**：这是「**添加当日事件**」页面的前端设计文档，用于规范前端与后端的接口交互，方便后端开发人员快速理解接口定义、数据格式与数据库设计。

## 1. 基础信息
| 项目 | 内容 |
| :--- | :--- |
| **组件文件名** | `MemorandumIndexView.vue`（实际功能：添加当日事件页面） |
| **前端技术栈** | Vue3 + Element Plus + Axios 1.14 |
| **核心功能** | 1. 输入事件内容；2. 选择事件日期；3. 提交至后端保存 |
| **所属模块** | 事件管理模块（Daily Event） |
| **依赖组件** | `ContentField.vue`（公共卡片容器） |

## 2. 前端页面布局与交互
### 2.1 页面结构（对应手绘设计稿）
页面由 1 个主表单构成，元素垂直排列：
1. **页面标题**：添加当日事件
2. **事件内容输入框**：单行/多行输入框，用于填写事件描述
3. **日期选择框**：日期选择器，格式为 `YYYY-MM-DD`
4. **提交按钮**：执行添加操作
5. **重置按钮**（可选）：清空表单

### 2.2 交互流程
1. **页面加载**：
   - 表单为空，日期输入框可默认选中今日日期（可选）。
2. **输入内容**：
   - 在「添加事件」输入框填写事件内容（如“开会”“写代码”）。
3. **选择日期**：
   - 在「添加日期」选择框选中对应日期（必填）。
4. **点击添加**：
   - 前端先做表单校验（非空、长度限制）；
   - 校验通过后调用后端接口；
   - 后端返回成功后，前端提示成功并重置表单。
5. **点击重置**：
   - 清空输入框和日期选择框。

## 3. 后端接口约定（核心）
### 3.1 接口基础信息
- **基础路径**：`/api`（与前端 Axios 配置一致）
- **数据格式**：JSON
- **统一响应格式**：
  ```json
  {
    "code": 200,
    "msg": "操作成功",
    "data": null
  }
  ```

### 3.2 新增当日事件接口
#### 3.2.1 接口信息
| 项 | 内容 |
| :--- | :--- |
| **接口名称** | createDailyEvent |
| **请求方式** | POST |
| **接口路径** | `/daily-events` |
| **功能描述** | 将用户输入的事件内容与日期保存到数据库 |

#### 3.2.2 请求参数（Body 体）
| 参数名 | 类型 | 必填 | 说明 | 示例 |
| :--- | :--- | :--- | :--- | :--- |
| `content` | String | 是 | 事件内容，长度建议不超过 500 | "完成数学作业" |
| `date` | String | 是 | 事件日期，格式严格为 `YYYY-MM-DD` | "2026-04-08" |

**请求示例**：
```json
{
  "content": "下午3点提交实验报告",
  "date": "2026-04-08"
}
```

#### 3.2.3 响应结果
**成功响应**（HTTP 200）：
```json
{
  "code": 200,
  "msg": "事件添加成功",
  "data": null
}
```

**失败响应**（HTTP 500/400）：
```json
{
  "code": 400,
  "msg": "日期格式错误",
  "data": null
}
```

## 4. 数据库设计（后端实现参考）
### 4.1 数据表名
`daily_events`（当日事件表）

### 4.2 表结构设计
| 字段名 | 数据类型 | 主键 | 非空 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `id` | BIGINT | ✅ | ✅ | 自增主键，事件唯一标识 |
| `content` | VARCHAR(500) | ❌ | ✅ | 事件内容 |
| `date` | DATE | ❌ | ✅ | 事件绑定日期（YYYY-MM-DD） |
| `create_time` | DATETIME | ❌ | ✅ | 创建时间，默认当前时间 |

### 4.3 示例数据
| id | content | date | create_time |
| :--- | :--- | :--- | :--- |
| 1 | 购买学习资料 | 2026-04-08 | 2026-04-08 10:00:00 |
| 2 | 复习C++算法 | 2026-04-09 | 2026-04-08 10:05:00 |

## 5. 前端校验规则（后端需兼容的输入）
为减少无效请求，前端会提前做校验，后端建议也做一层校验：
1. **`content` 非空**：禁止提交空字符串
2. **`content` 长度限制**：建议 1~500 字符
3. **`date` 格式校验**：严格匹配 `YYYY-MM-DD`
4. **`date` 逻辑校验**：可选择过去/未来日期（根据业务需求决定）

## 6. 错误处理规范
### 6.1 前端提示规则
| 场景 | 前端提示信息 |
| :--- | :--- |
| 表单校验失败 | “请输入事件内容” / “请选择日期” |
| 网络异常 | “网络异常，请稍后重试” |
| 服务器错误 | “服务器异常，请联系管理员” |
| 接口返回非200 | 直接展示后端返回的 `msg` |

### 6.2 后端错误码建议
| 状态码 | 含义 |
| :--- | :--- |
| 200 | 操作成功 |
| 400 | 请求参数错误（如格式错误） |
| 500 | 服务器内部错误 |

## 7. 注意事项
1. **日期格式统一**：前后端必须统一使用 `YYYY-MM-DD` 格式，避免时区或格式解析错误。
2. **唯一性约束**：`id` 字段需设置为自增主键，确保每条事件唯一。
3. **字符编码**：数据库和后端接口统一使用 UTF-8，避免中文乱码。
4. **接口路径一致性**：前端写死 `/daily-events`，后端接口需严格对应。
